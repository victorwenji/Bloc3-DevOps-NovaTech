Évolution recommandée

Le pipeline historique mélangeait build et déploiement avec des contrôles limités. La cible introduit une vraie étape de validation permettant de bloquer la livraison en cas d'échec des tests, du lint ou d'un contrôle de sécurité.

Choix des outils

Justification des principaux composants du pipeline.

  • Source
    GitHub centralise le code et permet de déclencher les workflows sur les événements Git. GitHub Actions reste cohérent avec l'hébergement du dépôt.
  • Setup
    actions/checkout et actions/setup-node permettent de préparer un environnement Node reproductible.
  • Build
    npm est utilisé pour installer les dépendances et construire le frontend React. Le package-lock.json permet de verrouiller les versions.
  • Validation
    Les tests automatisés, le lint et l'audit de sécurité doivent devenir des quality gates obligatoires avant toute livraison.
  • Deploy
    Le déploiement SSH reste possible pour l'infrastructure actuelle, mais doit privilégier une clé SSH, un utilisateur dédié et des mécanismes de rollback.

Recommandations

Évolutions prioritaires pour augmenter la robustesse du pipeline.

🛡 Quality Gates

Ajouter une étape de validation obligatoire avant le déploiement :

  • Tests unitaires
  • Tests d'intégration
  • Lint
  • Audit des dépendances
  • SAST

🚀 Déploiement

Faire évoluer le modèle SSH actuel vers un déploiement plus sûr :

  • Clé SSH dédiée
  • Utilisateur de déploiement dédié
  • Secrets GitHub Actions
  • Health-check après release
  • Rollback automatique

🌍 Multi-environnement

Séparer explicitement les environnements :

  • Development
  • Staging
  • Production

La promotion vers production doit dépendre de la réussite du staging.

📦 Évolution infrastructure

Si le projet monte en charge, envisager progressivement :

  • Images Docker immuables
  • Registry d'images
  • Déploiement versionné
  • Infrastructure as Code
  • Orchestration cloud / Kubernetes si nécessaire
Priorité recommandée

La priorité n'est pas de complexifier immédiatement l'infrastructure. Le meilleur gain à court terme consiste à sécuriser le pipeline existant : tests obligatoires → audit sécurité → staging → validation → déploiement par clé → health-check → rollback.
